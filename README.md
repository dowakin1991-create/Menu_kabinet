# KABINET — графік команди

Статичний застосунок: index.html для працівників, admin.html для адміністратора.
Проєкт Firebase: kabinet-graphik-v2. Збірка не потрібна.

## Запуск
1. Firebase Authentication: увімкнути Email/Password та Anonymous.
2. Firestore: опублікувати вміст firestore.rules.
3. GitHub Pages: гілка main, каталог / (root).
4. Адмінка: увійти створеним обліковим записом адміністратора.

## Доступ
Зміни, працівників і бенкети редагує лише UID адміністратора з js/config.js і firestore.rules.
Працівник відкриває головну сторінку, копіює свій код доступу та передає адміністратору.
Адміністратор натискає ім’я працівника й зберігає цей код у полі доступу.
Правила дозволяють працівнику записувати побажання лише для прив’язаного профілю.
Після очищення даних браузера код треба прив’язати заново.
Графік доступний для перегляду всім, хто відкрив посилання і отримав гостьову сесію;
це не закритий портал для конфіденційних даних.

## Чеки і повідомлення
Фото чеків додаються з телефона після збереження бенкету (до 8 фото). Зображення стискаються до JPEG і зберігаються окремими документами Firestore, до 700000 символів кожне. Відкрийте фото натисканням; повторне натискання збільшує його до розміру збереженого зображення. Видалення бенкету атомарно видаляє його фото. Оновіть firestore.rules перед використанням фото. Firebase Storage не потрібен. Квоти безкоштовного Firestore залишаються чинними. HTTPS-посилання також підтримуються.
Повідомлення передаються через системне меню «Поділитися»; токенів Telegram немає.
Перший графік порожній: адміністратор додає працівників і призначає зміни.

## Порядок працівників
Адміністратор може перетягувати рядки за ⠿ на комп’ютері або використовувати ↑/↓ (також на телефоні). Порядок зберігається автоматично для поточного місяця, відображається працівникам та в PNG. Перестановка виконується транзакційно за ID й не замінює паралельно змінені зміни.

Новий місяць під час першого відкриття адміністратором успадковує імена, ID та порядок з останнього попереднього створеного місяця. Зміни, вихідні, бенкети й фото не копіюються. Наявний місяць, зокрема навмисно порожній, не перезаписується. Прив’язка доступу зберігається завдяки незмінним ID.

## Реєстрація працівників
На головній сторінці є вхід, реєстрація (ім’я, пошта, пароль від 8 символів), відновлення пароля, повторне надсилання листа й перевірка підтвердження пошти. Після натискання посилання в листі треба повернутися до графіка та натиснути «Я підтвердив пошту». Код доступу передається адміну, який прив’язує його через картку працівника. Реєстрація на тому самому пристрої перетворює анонімний обліковий запис зі збереженням UID. Обліковий запис не створює новий рядок автоматично та не надає адмінських прав.

### Обов’язкове налаштування Firebase перед завершенням переходу
1. Проєкт **kabinet-graphik-v2** → Authentication → Sign-in method: Email/Password має бути ввімкнений. Не змінювати старий проєкт.
2. Firestore Database → Rules: опублікувати поточний `firestore.rules` з цього репозиторію. Альтернатива з авторизованого Firebase CLI: `firebase deploy --only firestore:rules --project kabinet-graphik-v2` з цієї папки.
3. Перевірити реєстрацію на реальну пошту, доставку листа, підтвердження, прив’язку адміністратором та вхід на іншому пристрої.

Публікація GitHub Pages **не публікує правила Firebase**. Поки крок 2 не виконано, перевірка підтвердження пошти діє лише в новому інтерфейсі; попередні серверні правила продовжують діяти. Нові правила зберігають читання графіка гостями, але редагування вихідних дозволяють тільки підтвердженому прив’язаному працівнику або адміну. Старим працівникам після публікації правил потрібно зареєструватися та підтвердити пошту. Адмінський UID не змінений.

## Закритий графік, Google / Apple та запам’ятовування входу
Відвідувачі бачать тільки реєстрацію/вхід. Вхід і підтверджена пошта самі по собі не дають читання графіка. Власник і схвалені адміни мають доступ; працівник — після прив’язки його UID до рядка. Адмін зберігає employeeAccess та teamAccess разом. Старі прив’язки отримують teamAccess під час наступного входу адміна. Стара teamAccess без чинної employeeAccess не дає доступу. Відкликання прив’язки одразу закриває графік. Не зберігаємо приватний графік у service worker чи постійному кеші Firestore.

Обов’язково повторно опублікувати `firestore.rules` у **kabinet-graphik-v2**. До публікації попередні серверні правила все ще дозволяють читання; прихований інтерфейс не є захистом API. Після оновлення правил власнику треба відкрити адмінку для перенесення старих прив’язок або повторно зберегти код доступу потрібного працівника.

Firebase Authentication → Sign-in method: увімкнути Google, обрати support email. Authentication → Settings → Authorized domains: додати `dowakin1991-create.github.io`. Apple: потрібні Apple Developer Program, Services ID, Team ID, Key ID та приватний ключ, налаштовані у Firebase Apple provider; redirect URI `https://kabinet-graphik-v2.firebaseapp.com/__/auth/handler`. Приватний ключ вводити тільки в Firebase, не в репозиторій. Якщо використовується Hide My Email, налаштувати Apple private email relay для листів Firebase. Google/Apple кнопки реалізовані, але їхню серверну конфігурацію з цього сеансу не змінено. Вхід через іншу пошту/Apple relay може створити інший UID; такий обліковий запис потрібно окремо схвалити, автоматичного об’єднання за іменем немає.

«Запам’ятати мене» зберігає Firebase-сеанс на пристрої; без прапорця — лише сеанс вкладки. Паролі програма самостійно не записує. Форми мають стандартні name/autocomplete для менеджерів паролів. Автозаповнення з Face ID залежить від iPhone та його налаштувань; це не власний passkey-вхід сайту.

## Прямі Web Push сповіщення (17.10.2026)
Клієнт і серверний код готові, але публікація GitHub Pages **не розгортає Cloud Functions**. До виконання кроків нижче сповіщення не надсилаються. Прив’язувати оплату або входити чужими обліковими даними автоматично не можна.

1. У Firebase **kabinet-graphik-v2** перевірити тариф. Cloud Functions потребують **Blaze** (прив’язаний платіжний акаунт; витрати залежать від використання). Перехід тарифу виконує власник. Налаштувати бюджетні сповіщення; вони не є жорстким лімітом витрат.
2. На комп’ютері встановити Node.js 22 і Firebase CLI. Завантажити цей репозиторій, відкрити термінал у його папці:
   ```sh
   npm install -g firebase-tools
   firebase login
   npm ci --prefix functions
   firebase deploy --project kabinet-graphik-v2 --only functions:kabinet-push
   ```
3. Перевірити, що розгорнуті `pushConfig`, `pushSubscribe`, `pushUnsubscribe`, `pushSchedule` у `europe-west1`. Тільки ці нові функції входять у codebase `kabinet-push`; існуючі функції інших codebase не змінюються.
4. Для push **не потрібно знову змінювати вже опубліковані правила**: `_pushPrivate` і `_pushDevices` закриті поточним `match /{document=**}`. Доступ до них має лише Admin SDK у функціях. Не відкривати ці колекції клієнтам. VAPID-ключі генеруються один раз сервером у транзакції; приватний ключ ніколи не потрапляє у GitHub чи браузер. Не видаляти `_pushPrivate/vapid`: заміна ключа потребуватиме перепідписки пристроїв.
5. На iPhone: Safari → Поділитися → На початковий екран. Відкрити нову іконку KABINET, увійти, отримати доступ до графіка, натиснути «Увімкнути сповіщення» та дозволити їх. Потрібна iOS 16.4+. На сумісному комп’ютері встановлення на екран не обов’язкове.
6. Адмін зберігає зміни і натискає «Сповістити команду». Це ручна дія; немає розсилки при кожному редагуванні. Перевірити реальну доставку із закритим застосунком на тестовому пристрої після розгортання. Звітується приймання push-службою, а не гарантована доставка/прочитання.

Вміст повідомлення фіксований: «Графік оновлено. Відкрийте кабінет, щоб переглянути зміни». Натискання відкриває захищений кабінет. Відкликані, вимкнені, непідтверджені облікові записи (крім незмінного власника) не отримують нових розсилок. Права перевіряються сервером; працівник не може надсилати повідомлення команді. Ліміт: 10 пристроїв на користувача; одна розсилка на хвилину для всієї команди. Вихід вимикає підписку поточного браузера. Push, уже прийнятий зовнішньою службою до відкликання прав, може ще надійти; він не містить приватних даних. Несправні endpoints 404/410 видаляються. Приватні дані не кешуються service worker. Оригінальний `kabinet-schedule` не змінюється.

Без входу в Firebase і прив’язки потрібного тарифу з цього середовища можна перевірити код та емулятор, але не активувати або довести реальну доставку на телефон.

Перевірка push: `npm ci --prefix functions`, `npm install`, `npm run test:push`. Емулятор використовує локальну Firestore та підставний відправник; реальні сповіщення тест не надсилає.
