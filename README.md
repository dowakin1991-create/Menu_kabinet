# KABINET — графік команди

Статичний застосунок: index.html для працівників, admin.html для адміністратора.
Проєкт Firebase: kabinet-graphik-v2. Збірка не потрібна.

## Запуск
1. Firebase Authentication: увімкнути Email/Password та Anonymous.
2. Firestore: опублікувати вміст firestore.rules.
3. GitHub Pages: гілка main, каталог / (root).
4. Адмінка: увійти створеним обліковим записом адміністратора.

## Доступ
Зміни, працівників і бенкети редагує лише UID адміністратора з js/config.js і firestore.rules.
Працівник відкриває головну сторінку, копіює свій код доступу та передає адміністратору.
Адміністратор натискає ім’я працівника й зберігає цей код у полі доступу.
Правила дозволяють працівнику записувати побажання лише для прив’язаного профілю.
Після очищення даних браузера код треба прив’язати заново.
Графік доступний для перегляду всім, хто відкрив посилання і отримав гостьову сесію;
це не закритий портал для конфіденційних даних.

## Чеки і повідомлення
Фото чеків додаються з телефона після збереження бенкету (до 8 фото). Зображення стискаються до JPEG і зберігаються окремими документами Firestore, до 700000 символів кожне. Відкрийте фото натисканням; повторне натискання збільшує його до розміру збереженого зображення. Видалення бенкету атомарно видаляє його фото. Оновіть firestore.rules перед використанням фото. Firebase Storage не потрібен. Квоти безкоштовного Firestore залишаються чинними. HTTPS-посилання також підтримуються.
Повідомлення передаються через системне меню «Поділитися»; токенів Telegram немає.
Перший графік порожній: адміністратор додає працівників і призначає зміни.

Історичні записи зі старої бази автоматично не копіюються.

- Транзакції зберігають актуальні дані; побажання редагуються по одному дню
  без перезапису інших днів або робочих змін.
- Підписка чекає обох джерел даних; старі callbacks після перемикання
  місяця і помилки доступу не показують хибний успіх.
- Збереження блокує паралельні дії на сторінці; контекст фото фіксується.
- Ім’я й прив’язка доступу змінюються атомарно.
- Список змінених днів зберігається локально окремо для кожного місяця,
  включно після перезавантаження. Він накопичувальний; підготовка повідомлення
  сама по собі не є підтвердженням його надсилання.
- При помилці запису користувач бачить повідомлення й може повторити дію.
- PNG 1–15 та 16–кінець створюється локально Canvas без зовнішнього рендерера.
- HTML із імен не виконується. Токен Telegram з оригіналу НЕ копіюється.
  Повідомлення надсилаються користувачем через системне меню «Поділитися».
- Автоматичного незворотного видалення старих чеків під час перегляду немає.

Токен бота, опублікований у старому репозиторії, власник має відкликати
через BotFather. Видалення токена тільки з нової версії не відкликає старий.
Публікація HTML/JS не змінює налаштування Firebase: правила доступу повинні
бути розгорнуті окремо згідно з розділом «Запуск».

## Перевірки

`npm test` — автономні регресійні тести Node.js, без пакетів і звернень
до робочої бази. Перевіряють паралельні зміни, валідацію дат, атомарність
профілю, видалення фото, порядок підписок і журнал сповіщень.
Модель Firestore в тестах імітується; перевірка розгорнутих Firebase Rules
та реального входу потребує тестового/адміністративного облікового запису.

елементи для роботи захисту. PNG показується у старому вікні результату.

Тести tests/legacy.test.cjs перевіряють збіг усіх ID початкової розмітки
та SHA-256 повного оригінального CSS, наявність обробників кнопок,
екранування імен і коректність рядкових UUID. Загалом: 14 тестів.

## Порядок працівників
Адміністратор може перетягувати рядки за ⠿ на комп’ютері або використовувати ↑/↓ (також на телефоні). Порядок зберігається автоматично для поточного місяця, відображається працівникам та в PNG. Перестановка виконується транзакційно за ID й не замінює паралельно змінені зміни.

Новий місяць під час першого відкриття адміністратором успадковує імена, ID та порядок з останнього попереднього створеного місяця. Зміни, вихідні, бенкети й фото не копіюються. Наявний місяць, зокрема навмисно порожній, не перезаписується. Прив’язка доступу зберігається завдяки незмінним ID.
